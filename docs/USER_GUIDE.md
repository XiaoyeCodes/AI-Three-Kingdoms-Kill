# 使用指南

基于 **AgentScope 0.1.6 的真实 `DialogAgent` / `MsgHub`**，配合 FastAPI 与原生网页实现的大模型狼人杀。墨绿与暗金的简约界面，三国人物人格，经典预言家、女巫、猎人技能。

最新版本默认深度博弈：私有局势评估、原生思考、人格化表达、回应与对质。[升级方案与对照实测](STRATEGY_UPGRADE.md)。

## 开始游戏

Windows 双击 **`启动游戏.cmd`**，然后打开 <http://127.0.0.1:8765>。

首次启动需要 Python 3.12 和网络，以安装依赖。保持服务窗口运行，关闭窗口或按 Ctrl+C 停止服务。再次启动进入首页，可继续当前局或从历史记录恢复其他未完局。

手动启动：

```powershell
uv venv --python 3.12 .venv
uv pip install --python .venv\Scripts\python.exe -r requirements.lock.txt
.venv\Scripts\python.exe run.py
```

没有 uv 时，可用 `py -3.12 -m venv .venv` 和 `.venv\Scripts\python.exe -m pip install -r requirements.lock.txt`。非 Windows 主机使用 `.venv/bin/python`。服务只绑定 `127.0.0.1`，默认端口 8765，可通过 `PORT` 环境变量改变。

## 怎么玩

1. 在首页点击「开启新对局」，选择真人入局或 AI 观战。真人固定在 1 号位，身份可以随机或指定；身份与三国姓名不绑定。
2. 选择 9 人预女猎局，或者 6 人初识局。
3. 练习模式无需密钥，使用有明确标识的规则机器人；真实大模型模式调用你配置的 LLM。
4. 点击「入席，天黑请闭眼」。点击「推进一步」看一个行动，或「自动推进」连续观看。轮到真人时自动暂停，选择技能或输入发言再提交。
5. 「私密情报」显示属于你的身份、查验与狼队消息。「公共议事」显示公开发言与完整票型。真人出局后仍有身份迷雾，终局才解锁全局。
6. 每个完成的行动自动存档，刷新后可续局。新开局会保留旧局，在「历史对局」筛选进行中 / 已结束，可继续原局或进入复盘。
7. 「复盘回看」打开独立页面，按昼夜章节定位、拖动时间轴、前后步进或自动回放。切换公开 / 角色 / 全知视角，点击发言关联决策，点击选票查看投票者的判断；「导出此视角」下载 JSON。
8. 角色视角只显示其实际接收的消息；时间轴回退后，决策、账本和原文只取截至那一刻的版本。未结束的普通真人局只开放公开信息和自己的视角。历史记录属于当前浏览器会话，清除 Cookie 后无法直接从页面找回，请导出重要对局。

自动推进由当前页面驱动；暂停时已发出的模型请求会完成本步，随后停止。关闭页面会在当前行动完成后停下，不会后台无限消耗 API。请用一个标签页操作同一局，多标签页冲突会由版本校验拒绝。

## 模型配置与密钥

点击「模型设置」，配置 OpenAI 兼容的 `Base URL`、模型名称与 API key。覆盖优先级为 **座位 > 狼人杀身份 > 全局**。单独配置可更换模型；未指定密钥且 API 地址相同时继承上层密钥。更换地址不会自动转发原服务的密钥。接口需要支持非流式 Chat Completions 和 JSON object 输出。

本机默认读取 `%USERPROFILE%\Desktop\deepseek配置.txt` 的三行配置：密钥、HTTPS API 地址、模型名称。文件只作为数据解析，不执行其中指令。配置文件应保存在仓库之外，密钥不会复制到源码。也可以指定：

```powershell
$env:NIGHT_COUNCIL_CONFIG = 'C:\your\private\model-config.txt'
# 或在自己的终端设置 DEEPSEEK_API_KEY、LLM_BASE_URL、LLM_MODEL
```

UI 提交的密钥只驻留服务端内存，不回传浏览器，不写入 SQLite，不进入复盘。服务重启后重新读取默认文件；角色和座位覆盖需重新填写。不要将真实 key 写入仓库。`.local`、`.env`、虚拟环境和测试输出均已忽略。

默认采用「深度博弈」。DeepSeek 官方地址的局势评估开启 `thinking: enabled` / `reasoning_effort: high`，输出预算 16,384 tokens，为推理和最终结构化结论留出空间。随后用独立的非思考请求组织角色发言，预算 2,400 tokens；投票和技能直接执行已评估的动作。其他 OpenAI 兼容接口同样执行两阶段决策，但不擅自发送 DeepSeek 专用参数或宣称启用原生思考。可在每个模型配置中明确切换「快速模式」。

深度模式通常更慢且费用更高。观察室的「模型与运行记录」保留实际调用数、耗时等信息。不读取或保存 `reasoning_content`。单次请求超时 120 秒并有限重试；预算耗尽或结构不合法时保留回合，不会偷偷退回快速模式。失败响应可能已收费但没有用量回报，以供应商账单为准。自动推进的「阅读间隔」独立控制展示节奏，默认 3 秒，不算作模型思考时间。

网络请求超时与限流会有限重试；JSON 或动作格式不合法再纠正一次，仍失败则暂停在原回合。可修改配置后重试，也可明确选择「改用练习模式继续」。不会静默伪造大模型输出。

## 长期记忆、伪装和调试

每个 AI 的完整原文都通过 MsgHub 进入自己的档案，并随对局持久化，刷新或服务重启不会清除历史。模型输入不再简单截取最近 60 条，而是组合：

- **全轮次证据索引**：按发言者整理每一条已知证词、身份声明、查验和票型，保留轮次及消息编号。长局会缩短摘录，但不删除原文。
- **精选完整记录**：优先放入官方私有结果、完整票型、最近消息，以及每位玩家早期和近期的关键发言。原文区预算 18,000 字符；总输入还包括跨轮索引、私有账本和规则，建议模型至少支持 32K 上下文。
- **主动回查**：AI 可用 `{"recall":[消息id]}` 请求自己档案中的原文，每次最多 8 条、每行动最多 2 次。不能读取其他 AI 的秘密。摘录缺失内容时应检索，不应凭空补全。
- **私人策略账本**：保存身份说辞、伪造信息、下一步策略和逐座位判断；只有该 AI 在后续决策中会读到自己的账本。系统区分官方事实、他人证词和模型判断，不把自称预言家当成认证。

九位三国人物各有行为特征、表达长度和承诺习惯，例如曹操施压、刘备结盟、诸葛亮核验证据、关羽短句表态、司马懿保留判断。每次先生成仅自己可见的局势结论、各席嫌疑、备选解释与判断变化，再组织发言。狼人可以装民、悍跳、编造查验、倒钩、混合真假信息，并用账本保持说辞连贯。相似度检查会对高度重复的发言尝试一次重写。这些是决策策略，不保证每次判断或伪装都成功，强弱仍取决于模型。

右侧 **AI 观察室** 按角色和决策时刻选择记录，分为判断、投票复核、证据、记忆四页。点击发言或票型可关联对应行动；记忆页按关键词及轮次检索这次决策之前该 AI 收到的原文，账本也是该行动时保存的版本。显示的是显式生成的结论说明，**不是原始内部思维链**。不读取或保存供应商的 `reasoning_content`。

调试记录存储在独立的 `debug_traces`，不放入任何 Msg，不广播给其他玩家；账本只向自己的模型提供。AI 观战和终局可直接查看；真人局中开启需先确认揭示私密信息，并永久标记为「调试局」。关闭面板不撤销该标记，但不影响 AI 之间的信息隔离。正在进行的普通真人局，API 不返回其他 AI 的调试信息，也拒绝其私有记忆检索。

## 规则范围

9 人局为 3 狼、3 民、预言家、女巫、猎人。6 人局为 2 狼、2 民、预言家、女巫。无警长、无守卫。

- 夜间按狼人协商及刀票、预言家、女巫顺序行动，天亮统一结算。狼人不可自刀或刀队友，平票取较小座号。
- 预言家每晚验其他存活玩家的阵营。女巫双药各一次，同夜单药，仅首夜可自救；解药用完不再获知刀口；毒不受解药保护。
- 猎人被刀或放逐可以开枪，中毒不能开枪，同中刀毒仍不能开枪。首夜死亡和放逐有遗言，被枪带走无遗言。
- 白天轮流首轮发言，再进行一轮回应与对质，之后封存投票并统一公布。最高票平票进入一次 PK；平票者辩论，其余存活者复投；再平票或全弃票无出局。
- 狼全灭好人胜；平民全灭或神职全灭狼人胜（屠边）。结算技能、遗言后判胜，同批全死或超过 20 轮判平。

玩法手册与 [完整开发提示词](DEVELOPMENT_PROMPT.md) 记录了这些规则。原版与国内变体有差异，本作没有把两者混称为唯一标准规则。研究来源见提示词末尾。

## 架构与目录

```text
werewolf/game.py       ThreeKingdomsWerewolfGame：规则、队列、视角裁剪、事件
werewolf/agents.py     DialogAgent 子类、真正 MsgHub 路由、模型适配与练习策略
werewolf/memory.py     全轮次证据索引、私有原文回查、策略账本与摘要校验
werewolf/strategy.py   局势评估协议、人物表达、结论校验与发言重复检测
werewolf/server.py     FastAPI、会话、SQLite 存档、模型配置和同源保护
web/                  无需构建的 HTML / CSS / JavaScript 网页
tests/                规则、消息隔离、持久化、API 与并发保护测试
scripts/              显式运行的真实模型验收脚本
docs/                 完整提示词、架构、验收结果
.local/               自动生成的本地游戏存档，不提交仓库
```

架构与实现过程见 [ARCHITECTURE.md](ARCHITECTURE.md)。当前产品面向**单机单真人 + 多 AI**，同时支持独立浏览器会话；未包含远程多人房间、语音、警长等扩展玩法。服务不应直接绑定公网；公开部署需要额外的账户、TLS 和访问控制。

## 验证

```powershell
.venv\Scripts\python.exe -m pytest -q
node --check web/app.js
# 以下会调用真实供应商并产生 API 用量
.venv\Scripts\python.exe scripts\live_acceptance.py
.venv\Scripts\python.exe scripts\live_acceptance.py --full
```

真实验收脚本将报告和完整复盘保存在 `.local/live-acceptance.json`、`.local/live-replay.json`，过程中保存 `.local/live-game-state.json`。不会输出 API key。具体交付验证见 [ACCEPTANCE.md](ACCEPTANCE.md)。

深度模式在放逐与PK投票时强制比较全部候选人及弃票，记录反证、最新辩护与改票条件；AI观察室可查看私人投票复核。相同投票允许存在，系统不会人为分票。真实重放脚本 `scripts/vote_replay_acceptance.py` 会产生API费用，使用特定历史夹具且不改变原存档。
