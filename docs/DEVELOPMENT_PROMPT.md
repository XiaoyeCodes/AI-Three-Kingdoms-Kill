# 完整开发提示词：三国 · 夜议

你是负责交付的全栈工程师与游戏规则设计师。开发一个真正可运行、可复盘的大模型狼人杀网页游戏，名称为「三国 · 夜议」。三国只赋予人物姓名、语气和人格，不改变狼人杀的身份技能与阵营。交付可运行源代码、明确的规则、启动脚本、验证报告及使用说明，不以静态展示或模拟 LLM 输出代替完成。

## 体验与可玩性

- 高级简约网页界面，墨色、暖白、暗金为主色；桌面三栏布局，手机可用。清楚区分公共发言、私密情报、待执行行动和复盘。
- 默认 9 人局：3 狼人、3 平民、1 预言家、1 女巫、1 猎人；提供 6 人教学局（2 狼、2 民、预、女）。无警长，降低首次学习成本。
- 真人入局与 AI 全自动观战均可玩。真人占一个席位，能发言、投票、参与狼队协商、查验、用药、开枪；出局后可继续以受限视角观战，结算才揭示身份。
- 支持逐步推进与自动推进；轮到真人时自动等待；刷新恢复同一局；能暂停、重新开局、下载复盘。
- 提供明确标识的无需密钥「练习模式」，不得把规则机器人称为真实 LLM。真实模式使用 OpenAI 兼容接口，允许全局、身份角色和座位逐级覆盖模型、URL、API key。
- 人格包括谨慎推理、激进施压、善于结盟等。模型必须根据已知发言、票型和私人情报行动；允许游戏内诈身份、悍跳和辩驳。模型不得知道不属于自己的隐藏信息。

## 明确规则合同

夜间狼人协商并秘密投票选择非狼目标（平票按固定座次决断），预言家每夜查验其他存活者阵营，女巫拥有各一次解药和毒药，同夜至多一瓶，仅首夜可以自救；解药用尽后不再告知刀口。全部夜间行动完成后统一结算，先毒药后狼刀效果，毒不受解药保护。夜里被刀/毒的角色在天亮之前仍可行动。

白天按轮换座次依次首轮发言，再让全员进行回应与对质，之后同时封存投票并统一公布，不允许后投票者看到本轮他人的选票。可弃票。最高票平票时，平票者再辩论一次，其他存活玩家在平票者中复投；再次平票或全弃票则无人出局。被放逐者及首夜死亡者有遗言。猎人被狼刀或放逐后可选择一名存活者开枪，也可不开枪；被毒死不能开枪，毒与刀同中仍不能开枪。技能与遗言结算后判胜。

所有狼人出局则好人胜；所有平民或所有神职出局则狼人胜（屠边）；双阵营同批全部死亡则平局；最多 20 个昼夜后判平。禁止把狼人数达到好人数写成屠边胜负。不同桌游原版/网杀规则存在差异，以上为本产品明确采用的变体，界面规则页须完整披露。

## 系统架构

1. 游戏控制层：`ThreeKingdomsWerewolfGame` 是唯一裁判。显式状态机、行动队列、合法目标校验、药品和弹药资源、死亡批处理、PK 复投和胜负判定。LLM 仅提议行动，不能直接修改全局状态。
2. 智能体交互层：真正使用 AgentScope 的 `msghub` / `MsgHubManager`。公开频道、狼人频道、法官到单人的私密频道独立作用域，不同时嵌套；所有通信只经消息中心广播。投票先单人提交，结算统一公开。
3. 角色建模层：每位玩家使用真正的 `DialogAgent` 子类，系统提示词由规则、角色和人格组成，记忆通过 MsgHub 接收。锁定 AgentScope 0.1.6，避免新版移除 DialogAgent 后假装兼容。
4. 模型适配层：OpenAI 兼容 API；严格 JSON 动作、有限上下文、超时、有限重试、token 统计；错误保留当前回合并可重试或显式切换练习模式。不要静默伪造模型结果。
5. 服务层：FastAPI 提供同源 API 与静态资源，单局串行锁与回合版本防重复提交；会话 cookie 隔离游戏；SQLite 持久化不含密钥的状态与事件。密钥仅驻留服务进程内存，默认配置从用户指定的本机文件读取，不传回浏览器，不写入复盘。
6. 表现层：HTML / CSS / JavaScript，构建依赖最少化；服务端裁剪视角，前端不可收到真人不知道的身份、夜间目标或私密发言。AI 观战是明确标识的上帝视角，不可途中转换为真人作弊。

## 实施阶段和完成标准

- M1 研究与规格：核对官方框架源码、经典规则原文，形成规则合同、开发提示词、架构和可检验的任务清单。
- M2 规则内核：构建状态机及事件模型，用有意义的测试覆盖夜间同时死亡、用药限制、猎人触发、平票、屠边、非法动作及消息隔离。
- M3 AgentScope 与模型：验证真实 DialogAgent / MsgHub 的连接，完成练习和真实模型两条路径；用提供的 DeepSeek 配置做真实调用验证，绝不输出密钥。
- M4 网页交互：完成创建房间、规则、模型配置、身份、发言与技能、自动/手动推进、票型和终局复盘；前端交互通过本地浏览器验收。
- M5 持久化与验收：跑完整练习对局及真实 LLM 完整对局，验证刷新恢复、错误恢复、并发重复请求、视角和密钥隔离。交付启动说明与实际测试结论。

## 2026-10-14 补充要求：跨轮记忆和调试

AI 不得仅依赖滑动窗口而丢失早期证词。每个玩家保留自己的完整消息档案，并在每次决策时读取覆盖所有轮次与发言者的证据索引、精选原文及自己的私有策略账本；可按消息编号主动回查原文。身份声明和模型判断必须与法官确认的事实分开，其他人的私密信息不能通过检索泄露。旧存档应向后兼容。

把性格落实为不同的信任阈值、攻击性、藏信息方式和交流风格。狼人应能选择并延续装民、悍跳、伪造查验、倒钩与迷惑策略，不机械集体跳预言家；私人账本追踪已经编造的说辞，避免无故遗忘和改口。

增加网页侧栏调试观察室。展示模型显式输出的简短决策摘要、行动意图、引用证据、长期记忆统计和私有账本，不展示原始内部思维链。调试轨迹独立保存，不进入 MsgHub、其他 AI 提示词或公共记录；只有该 AI 会在后续读到自己的账本。观战和终局可见，真人游戏需明确开启并标记为调试局，防止无提示地泄露身份。允许搜索某个 AI 自己的历史记忆并查看原文。

验收新增覆盖：20 轮每位玩家的原文与索引完整；早期证词可被模型检索；其他角色私密 ID 不可读；调试与账本不被广播；存档恢复后记忆、策略与调试轨迹一致；真人视角服务端拒绝未开启调试的私有查询；真实 LLM 生成摘要与策略账本，并能完成对局。


## 博弈质量验收补充

默认采用深度决策，DeepSeek 官方接口启用原生思考与充足输出预算。把独立的私有局势判断和公开角色表达分成两个阶段，投票与技能直接执行经校验的决策。保存简短嫌疑估计、备选解释、判断变化与行动目标，不采集原始内部思维链。

为每个人物提供不同表达长度、承诺方式和互动习惯，允许结盟、辩护、反驳与有目的的游戏内欺骗。对高度重复的发言尝试一次重写。不要用统一的“核对票型”套话代替实质决策。

规则上下文必须提供公开板子组成和本轮已发言/尚未轮到的名单。不得把未轮到误判为沉默，不得编造首日票型，不得把内部事件编号当成玩家座位。普通死亡不公开身份和死因。

前端显示实际请求阶段、耗时、调用数及供应商可用的推理用量。阅读间隔与思考时间分开标注。可明确切换快速模式，禁止错误后静默降级。

除了规则回归，使用固定矛盾局面、真实查验投票、狼人伪装连续性进行真实模型验证；记录成本、耗时及公开发言差异。小样本不足以声称胜率提升。方案和证据记录在 STRATEGY_UPGRADE.md。

深度投票须复核本人收件档案，比较全部合法候选人与弃票，区分重复指控和独立证据，回应目标最新辩护、记录最强反证及改票条件。允许合理一致投票，禁止人为分票。选票和私人复核对其他玩家保密；工程结构校验不等于策略效果认证。
