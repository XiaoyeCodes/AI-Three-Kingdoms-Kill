# 产品复查与体验升级

本轮围绕“进入游戏、持续游玩、理解 AI、回顾一局”四个环节重新组织产品。实现于 2026-10-15。

## 复查结论

| 原问题 | 对体验的影响 | 本轮实现 |
| --- | --- | --- |
| 开局配置承担了首页的全部职责 | 返回产品后缺少明确入口，不知道从哪里续局 | 独立首页，提供新对局、继续对局、最近故事与九位人物展示 |
| 存档只有当前一局 | 新开局会覆盖旧局，难以形成持续游玩的积累 | SQLite 逐局保存，历史列表按最近保存排序，可筛选进行中 / 已结束并恢复旧局 |
| “复盘”只是下载文件 | 用户难以回到某个发言或关键票型 | 独立复盘页，昼夜章节、时间轴、前后步进、自动回放、类型筛选和视角导出 |
| 观察室堆叠调试字段 | 很难把某句话与它对应的判断、证据联系起来 | 共用观察组件，分成判断、投票复核、证据、记忆四页；发言和选票可关联决策 |
| 缺少角色形象，字体与面板过于生硬 | 玩家认人和阅读成本高，三国人格难以形成印象 | 九张统一风格的人物插画、中文无衬线字体、墨绿暖金配色、圆角卡片和窄屏布局 |

## 关键交互

- **首页**：有未完成对局时优先继续当前未完局，否则继续最近未完局。最近记录可进入复盘或续局。
- **历史对局**：新建、切回和每步行动均保存记录；浏览复盘不替换正在玩的局。已结束对局进入复盘，未结束对局可恢复原行动队列。
- **复盘**：章节定位、拖动时间轴、逐条回放。点击“查看这次决策”会把时间轴定位到对应事件；点击票型中的选票，可对照投票者的复核记录。
- **观察室**：优先呈现结论和判断变化，随后按需展开逐人嫌疑、候选人反证、原文引用与私人策略。运行信息折叠收纳。
- **记忆原文**：按关键词与轮次检索这次决策之前、该角色实际收到的消息。不会使用它后来的记忆来解释早先的决定。
- **移动端**：保留全部导航，三栏纵向排列，时间章节横向滚动，头像列表可以在窄屏阅读。

## 复盘的信息边界

`werewolf/replay.py` 直接投影已保存的数据，不构建智能体，也不调用模型。公开视角、单角色视角和全知视角均由服务端检查权限。

公开视角只显示公开记录。角色视角只显示该角色实际接收的消息和它自己的决策；狼队成员身份按规则已知，其他身份保持隐藏。已结束局、AI 观战或明确开启的调试局可查看任意角色及全知视角。未结束的普通真人局只开放公开信息和真人自己的视角。

回退时间轴后，消息、决策摘要、引用原文和账本按事件编号截断。存活状态由截至该时刻的公开死亡公告重建，不能直接套用最终结果。未来时间轴只提供阶段与事件类型，不提供未来文本、行动者或目标。

观察室展示模型显式生成的结论摘要与证据，不读取或保存原始思维链。旧存档没有投票复核字段时会如实提示，练习规则策略也有明确标识。

## 验收

- 本地自动测试 **86 passed**，包含 10 项新增历史、迁移、恢复、会话隔离、时间截断、私有证据与记忆检索验证。
- 浏览器实际跑通新局 → 自动推进 → 终局 → 历史保留，以及历史真实模型对局的复盘、视角切换、时间步进、暂停、筛选与 JSON 导出。
- 桌面默认视口和 390px 手机视口检查；首页、对局、复盘均无横向溢出，头像正常加载，验收路径中控制台无应用错误。
- 截图使用独立验收数据库；真实模型复盘取自此前完成的六人对局。本轮页面验收未额外调用付费模型。

## 当前边界与后续优先级

历史属于本机浏览器会话，尚无账户登录和跨设备同步；清除 Cookie 后无法从页面直接找回，应导出重要对局。旧版本已覆盖的对局无法通过本轮数据库迁移恢复，迁移会保留旧版本最后存档。

博弈质量仍需独立评估。下一步应优先补足真实模型的固定场景回归，记录事实引用错误、独立证据来源、改票合理性和伪装一致性，再比较不同模型与策略。UI 和结构测试通过不能证明推理水平提高；最新独立投票协议的完整真实模型回归尚未完成；此前验收遇到供应商额度不足。
