# 博弈质量升级

## 问题定位

上一版能走完规则流程，也能隔离私有信息，但这些验证不能说明它好玩。三个实际缺陷是：DeepSeek 思考被关闭，单次 1,400 token 输出预算偏小；所有角色使用类似的通用推理话术；每人一轮发言后立即投票，先说话者无法回应后续指控。最后 250ms 的自动推进间隔也不给人阅读时间。

## 方案选择

| 方案 | 本次取舍 |
| --- | --- |
| 原生模型思考 | 默认开启 DeepSeek 高强度思考，提供 16K 输出预算；预算不足明确失败，不关闭思考兜底 |
| 私有判断与公开表达分开 | 采用。先形成简短局势结论、各席嫌疑、备选解释、行动目标和判断变化，再用个人风格组织发言；技能无需额外表达请求 |
| 长期证据与策略笔记 | 保留并接入新阶段。每个人只使用自己的档案；不是九个玩家共享一个分析结果 |
| 多模型混战 | 已有角色/座位配置可支持，但不把换模型当成解决信息结构与游戏机制问题的替代品；其他模型未在此次真实测试中验证 |
| 专门训练的策略网络或外部推演器 | 暂不加入。需要训练数据、独立评估与较大维护成本，不能假称几段提示词就复现论文系统 |
| 人为延时 | 仅作为明确标注的阅读间隔，可选 0/3/6/10 秒，不计入思考耗时 |

DeepSeek 官方接口明确区分思考开关、推理力度和输出预算，且思考模式的 temperature 不生效，因此评估阶段不靠提高 temperature 假装“更独立”。[官方接口文档](https://api-docs.deepseek.com/api/create-chat-completion/)

狼人杀研究中有将自然语言交互与专门策略推理分离的方案。例如 Wu 等的 Thinker 采用人类对局数据与强化学习。本实现只借鉴职责分离，不包含其训练出的模块，也不引用其胜率作为本产品效果。[论文](https://arxiv.org/abs/2402.02330)

## 实现

`DialogAgent → 私有证据包 → 局势评估 → 合法动作校验 → 人格化表达（发言时）→ MsgHub`。

局势记录包含简短结论、判断变化、带证据编号的嫌疑估计、备选解释及其弱点、锁定的动作与目标。它不是原始内部思维链。数据只保存在本人的 notebook 和人类可见的调试记录；公开频道只拿到最终发言，其他模型不会收到该记录。原生推理正文不读取、不持久化，仅使用供应商的用量统计。

表达阶段使用独立人物声音和最近对话，不能改变锁定动作，也不能把消息编号当成座号。高度复读时最多重写一次。概率是模型自己的主观判断；引用编号经过所属档案过滤，但系统不声称能自动证明每句推断正确。

白天增加全员回应与对质轮次。真人也有回应机会。法官仍掌握规则和胜负，LLM 只能提议合法行动。旧存档可恢复，已排好的旧日间队列不会强行重排，从下一次 day_start 开始使用新流程。

## 可复现验证

运行 `python scripts/strategy_acceptance.py` 对同一局面使用四个人格分别执行快速/深度模式，另测预言家真实查验投票及狼人的既有伪装。运行 `python scripts/deep_game_acceptance.py` 做六人真实完整集成测试。两个脚本均会产生 API 费用；输出位于被忽略的 `.local` 目录，不含密钥或原始思考正文。

第一次配对测试中，快速/深度都在 4/4 样本引用了构成矛盾的两条证词。深度平均 15.23 秒，快速平均 4.20 秒；四人发言的最大两两字符相似度为 0.301 / 0.457。深度四例合计 28,784 tokens，快速 8,897 tokens。预言家投给真实查验为狼的目标。样本小、输出有随机性，不能推断总体胜率或宣称深度模式必然更聪明；相似度只帮助发现复读，不是推理质量分数。

该次测试暴露“消息编号被念成玩家座号”的表达问题，随后将表达包中的事件编号移除，并加入显式说明。后续复测与整局结果见验收报告。

最终修订同时移除表达包的事件编号字段与生成笔记中的内部编号写法，并校验公开发言中的日志编号和不存在的玩家座号；不合格表达进入有上限的重试。原始证词不改写。深度评估与表达各自使用单一输出协议，避免旧版一次性 JSON 要求与分阶段协议冲突。最终真实行动复测用时30.01秒、2次请求、评估格式重试0次，正确引用玩家及游戏日；自动测试67项通过。

## 封存投票的独立复核（追加）

核对用户原局第二天的记录，5、6、7、8、9号都投1号，理由集中于弃票和较晚跳预言家。这些记录没有深度评估字段，属于升级前流程。实际选票按玩家私有路由，所有人提交后才公布，未发现后投票者读取前人选票；同质化来自公开讨论与决策缺少比较，不能把一致投票本身当作泄漏证据。

深度模式的投票及PK投票现在附加专用协议：按玩家整理当天发言索引（只读本人的收件档案，长文标注截断且可回查），比较全部合法候选人与弃票，为每个选项记录支持、最强反证或误杀代价，复核指控来源、目标最新辩护、最终取舍与改票条件。多个玩家重复同一条指控不作为多份独立证据；晚跳神职与未表态不能单独证明狼人；没有对跳也不等于身份认证。

这些是模型生成的简短判断记录，不是原始思维链。结构校验不声称能够证明推断正确。证据引用限制在本人的档案；完整复核不进入MsgHub，只有最终选票私下交给法官。不会强制分票、随机换目标或凭全局真身份纠正AI。快速模式仍使用原有单次输出协议；该强制复核只用于深度模式。

新增调试侧栏展示候选人比较、来源核对和改票条件。自动测试覆盖候选人缺失/重复、PK范围、早期与最新原话、跨玩家秘密隔离、封存选票、失败不投票和HTTP 402提示。最新自动测试结果见验收报告。真实重放脚本为 `scripts/vote_replay_acceptance.py`，不写入原始存档。首次真实请求返回HTTP 402（[DeepSeek官方说明：余额不足](https://api-docs.deepseek.com/quick_start/error_codes/)），未生成选票，已停止重复调用。此次真实博弈质量复测仍待可用额度，不能把上一版整局结果当作新复核的效果证明。
